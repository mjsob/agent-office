# 작업 효율 감시를 실행하세요

## 시작하기 전에 확인하세요

설치본이나 실행 중인 Office 서버를 바꾸지 않고 사용해요.
Python 3와 기존 `office bg`를 사용해요.
WSL과 맥에서 같은 Python 명령으로 실행해요.
감시 전용 대화는 제외하세요.
`office continue`로 이어진 감시 대화도 자동으로 제외해요.
기본 감시 기간은 시작부터 7일이에요.
파일 변경은 60초마다 확인해요.
변경 기록이 생기면 15분 동안 모아서 AI 검토를 요청해요.
변화가 없으면 AI를 깨우지 않아요.

## 실행하기

최초 한 번 기준 기록을 만들어요.
`ROOT`, `OUT`, `SESSION`은 저장소, 결과 폴더, 감시 대화 번호로 정하세요.

```sh
python3 "$ROOT/tools/efficiency_watch.py" init --root "$ROOT" --output "$OUT" --exclude-session "$SESSION"
```

일상 감시용 작업을 따로 등록하고 맡으세요.
해당 작업 번호로 `office bg`를 실행하세요.

```sh
office bg 작업번호 "변경분을 기다려" "python3 '$ROOT/tools/efficiency_watch.py' watch --root '$ROOT' --output '$OUT' --exclude-session '$SESSION'"
```

변경 묶음이 준비되면 명령이 끝나고 Office가 담당자를 깨워요.
`cursor.json`의 `pending.path`에 있는 파일을 읽으세요.
감시 대상 원본은 읽기만 하세요.
요청 변경, 입력 변경, 외부 대기와 실제 처리를 구분해요.
반복 검증은 코드·입력·환경이 같다는 근거가 있을 때만 낭비 후보로 봐요.
완료 보고와 후속 계획을 대조해 우회와 재작업을 확인해요.
시간이나 대기 차례 수만으로 낭비라고 판단하지 않아요.
이미 알린 사건은 다시 알리지 않아요.
확인한 문제만 사용자에게 짧게 알리고 담당자에게 근거와 조치를 전해요.
다른 대화에 보내는 감시 알림은 본문을 `[효율 감시]`로 시작하세요.
이 접두어가 있는 담당자의 메시지는 다시 수집하지 않아요.
다른 대화로 보내는 메시지는 기존 `office` 명령에 대상 대화의 `OFFICE_SESSION`과 요청의 `OFFICE_JOB`을 지정해요.

검토 근거를 결과 폴더에 저장한 다음 해당 묶음을 확인 처리해요.

```sh
python3 "$ROOT/tools/efficiency_watch.py" ack --root "$ROOT" --output "$OUT" --exclude-session "$SESSION" --batch-id 묶음번호
```

만료 전이면 같은 작업으로 `office bg`를 다시 실행하세요.
만료되면 남은 변경을 검토하고 일상 감시 작업을 마무리해요.
기간을 자동으로 연장하지 않아요.

## 문제가 생겼을 때

**감시 명령이 종료됐어요**

로그의 `review_ready`, `expired`, 오류 내용을 확인하세요.
미검토 묶음이 있으면 먼저 검토하세요.
재실행해도 같은 묶음을 보존해요.

**대화 기록을 읽지 못했어요**

`cursor.json`의 `errors`를 확인하세요.
읽기에 실패한 기록은 다음 확인 때 다시 읽어요.
같은 대화에서 3번 연속 실패하면 다음 변경 묶음에 오류를 넣어요.
복구 전까지 같은 오류로 다시 알리지 않아요.
원본 상태 파일을 고치지 마세요.

**진행 숫자가 바뀌어도 AI가 깨어나지 않아요**

수시 진행 숫자와 진행 알림은 검토 대상에서 제외해요.
작업 상태, 진행의 처리·대기 전환, 실제 결과 기록은 확인해요.
보관 처리로 옛 메시지가 짧아져도 새로운 변경으로 세지 않아요.
진행 정체 시간만으로 자동 경고를 보내지는 않아요.

## 삭제하기

일상 감시 작업의 백그라운드 프로세스를 종료하고 작업을 마무리하세요.
결과 폴더는 필요한 근거를 보관한 뒤 삭제하세요.
다른 대화의 기록은 삭제하지 마세요.
