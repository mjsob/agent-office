# 같은 검증 결과를 재사용하세요

## 시작하기 전에 확인하세요

입력 파일만으로 결과가 정해지는 정적 검증에 사용하세요.
검증 코드와 참조하는 자료·설정·잠금 파일을 모두 `--input`에 넣으세요.
명령 인자에 있는 기존 파일과 폴더도 자동으로 확인해요.
출력 경로를 명령에 전달한다면 `--artifact`로 함께 지정하세요.
폴더를 지정하면 하위 파일과 링크가 가리키는 내용도 확인해요.
실서버·외부 API·현재 시각·실제 화면 상태를 확인할 때는 원래 검증 명령을 직접 실행하세요.
명시하지 않은 외부 자료의 변경은 자동으로 알 수 없어요.

## 실행하기

저장소 최상위에서 실행하세요.

```sh
python3 tools/verify_once.py --static --name verify-once-regression \
  --input tools/verify_once.py --input tests/test_verify_once.py \
  -- python3 -I tests/test_verify_once.py
```

처음에는 검증을 실행하고 성공 기록을 저장해요.
같은 명령을 다시 실행하면 입력·명령·환경·실행 환경·로그가 같은지 확인해요.
조건이 맞으면 `reused`를 출력하고 이전 성공 기록을 사용해요.
기본 유효기간은 1시간이에요.
`avoided_command_seconds`는 건너뛴 검증 명령의 이전 실행 시간이에요.
실제로 줄어든 전체 시간과는 달라요.

결과 파일도 확인하려면 `--artifact 결과경로`를 추가하세요.
결과가 바뀌었거나 없어졌으면 검증을 다시 실행해요.
실패·시간 초과·실행 중 입력 변경은 성공 기록으로 저장하지 않아요.
같은 이름의 검증이 동시에 시작되면 먼저 시작한 검증이 끝날 때까지 기다려요.

검증 기록과 로그는 `.office/verification-cache/`에 저장돼요.
검증 자체가 몇 분 넘게 걸리면 기존 작업의 `office bg`로 실행하세요.

## 문제가 생겼을 때

**성공 기록이 있어도 다시 실행돼요**

환경 변수나 설치된 Python 패키지가 달라져도 다시 실행해요.
변경이 의도한 것인지 확인하세요.
다시 실행할 때 `--force`를 붙이면 이전 성공을 재사용하지 않아요.

**입력이 바뀌었다는 메시지가 보여요**

다른 작업이 같은 파일을 수정 중인지 확인하세요.
검증이 입력 폴더 안에 결과나 임시 파일을 만들었다면 입력과 출력 경로를 나누세요.

**검증이 실패했어요**

출력에 표시된 로그 파일을 확인하세요.
문제를 고친 뒤 같은 명령을 실행하세요.

## 삭제하기

`.office/verification-cache/` 폴더를 지우면 저장한 검증 기록과 로그가 삭제돼요.
소스 파일과 검증 결과물은 그대로 남아요.
